# قطّة الربع ☕

دفتر عربي للاستراحة: قطّة شهرية، سجل الربع، دفعات كاملة أو جزئية، مصاريف مدفوعة والتزامات قادمة، وأرشيف الشهور. الواجهة تعمل على GitHub Pages، والحفظ المشترك ودخول المسؤول عبر Supabase.

**الوضع الحالي:** الصفحة متصلة بمشروع Supabase، وحُفظت أسماء الربع الـ١٢ وألقابهم في دفتر سبتمبر ٢٠٢٦، بقطّة ٢٠٠ ريال للشخص (الإجمالي ٢٬٤٠٠ ريال)، وأمينها حمدان (أبو ذنب). لم تُسجّل أي دفعات أو مصاريف مسبقًا. الموقع منشور على [GitHub Pages](https://thedigitalstory.github.io/qattat-alruba/)، وحساب المسؤول جاهز. المعاينة بهذه الإعدادات تعرض السجل الحقيقي المشترك.

[افتح الموقع](https://thedigitalstory.github.io/qattat-alruba/) · [مستودع المشروع](https://github.com/thedigitalstory/qattat-alruba)

## جرّب الصفحة

افتح `dist/index.html` أو شغّل من هذا المجلد:

```bash
python3 -m http.server 4173 --directory dist
```

ثم افتح `http://localhost:4173`. لا تحتاج تثبيت حزم أو عملية بناء. الخط العربي ومكتبة الاتصال محفوظان مع الصفحة. للتشغيل الحقيقي استخدم HTTPS.

## ١. جهّز قاعدة البيانات

1. افتح [Supabase](https://supabase.com/dashboard)، أنشئ حسابًا ومشروعًا جديدًا، وانتظر اكتمال تجهيزه.
2. افتح **SQL Editor → New query**.
3. انسخ كامل ملف `supabase/setup.sql`، ألصقه في المحرّر واضغط **Run**. سينشئ دفترًا فارغًا وصلاحيات القراءة والتعديل. تشغيل الملف مرة أخرى لا يمسح بياناتك.
4. اختياريًا نفّذ `supabase/initialize-roster.sql` لإضافة أسماء الربع للشهر الحالي بمدفوعات صفرية؛ لا يستبدل شهرًا موجودًا. هذا منفّذ بالفعل في المشروع المتصل.
5. من **Authentication → Users → Add user → Create new user** أضف بريد المسؤول وكلمة مروره، وفعّل تأكيد البريد التلقائي إن ظهر الخيار. احتفظ بكلمة المرور عندك؛ لا تضعها في ملفات الموقع.
6. انسخ **User UID** للحساب الجديد. افتح `supabase/add-admin.sql` واستبدل `REPLACE_WITH_ADMIN_USER_UUID` بالمعرّف، ثم نفّذ الاستعلام في SQL Editor. هذا هو ما يمنح الحساب صلاحية التعديل.
7. من إعدادات Auth عطّل السماح بالتسجيل الجديد إذا لم تكن تحتاجه. إنشاء حساب وحده لا يمنح صلاحية المسؤول.

## ٢. اربط الصفحة

من نافذة **Connect** أو إعدادات المشروع انسخ **Project URL**، ومن **Settings → API Keys** انسخ مفتاح **Publishable** (أو مفتاح `anon` القديم).

افتح `dist/config.js` وضع القيم بين علامات الاقتباس:

```js
window.QATTA_CONFIG = Object.freeze({
  supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
  supabaseKey: 'YOUR_PUBLISHABLE_KEY'
});
```

المفتاح العلني مخصص للمتصفح؛ الحماية تتم بصلاحيات قاعدة البيانات. لا تستخدم `service_role` أو `sb_secret_...` إطلاقًا. ولا تضف كلمة مرور المسؤول إلى هذا الملف.

عند وجود بيانات الربط يُعرض السجل المشترك. إذا فشل الاتصال يظهر ذلك بوضوح، ولا تُستبدل بياناته ببيانات المعاينة. بعد تسجيل الدخول وفتح أول شهر يظهر خيار إضافة أسماء الربع الـ١٢ المحفوظة، بمدفوعات صفرية.

## ٣. انشر على GitHub Pages

1. أنشئ مستودعًا في حساب GitHub وارفع محتويات **المشروع كاملًا** إلى الفرع `main`، بما فيها `dist` وملف `.github/workflows/pages.yml` المخفي. لا ترفع ملفات النسخ الاحتياطية الشخصية.
2. من المستودع اختر **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. افتح **Actions → Publish Qatta to GitHub Pages → Run workflow**. وإذا حدث رفع جديد إلى `main` يعمل النشر تلقائيًا.
4. بعد نجاح العملية، يظهر رابط الصفحة في **Settings → Pages**. الرفع ينشر مجلد `dist` وحده.
5. في Supabase، ضمن **Authentication → URL Configuration**، ضع رابط الموقع النهائي في **Site URL**.

يمكن أيضًا رفع **محتويات** `dist` مباشرة إلى `public_html` في هوستنقر، مع نفس ربط Supabase.

## ٤. أول قطّة حقيقية

1. افتح الموقع واضغط **دخول المسؤول**، ثم استخدم اسم المستخدم أو البريد مع كلمة المرور. حسابات البريد الحالية تعمل كالمعتاد.
2. افتح **إعدادات الاستراحة** لتغيير الاسم وأمين القطّة والمبلغ وبيانات التحويل.
3. دفتر سبتمبر ٢٠٢٦ جاهز بأسماء الربع. للشهور التالية اختر الشهر واضغط **فتح دفتر الشهر**، وانسخ الأسماء من الشهر السابق بمدفوعات صفرية. يمكنك إضافة أشخاص آخرين لاحقًا.
4. بعد التأكد من وصول الحوالة اضغط **تسجيل** بجوار الاسم. المبلغ هو **إجمالي ما دفعه لهذا الشهر**؛ مثال: إذا دفع ١٠٠ ثم ١٠٠، يصبح الإجمالي ٢٠٠. يمكن تعديل الاسم والدفعة والملاحظة من النافذة نفسها.
5. أضف الالتزامات وعلّم المدفوع منها. الالتزام غير المدفوع لا يُخصم من رصيد الصندوق إلا عند تعليمه مدفوعًا.
6. الشهر الجديد يستطيع نسخ أسماء الربع من آخر شهر سابق، بمدفوعات صفرية. لا تُنسخ المصاريف ولا يُرحّل رصيد الشهر السابق تلقائيًا. **كل شهر مستقل ماليًا**.
7. شارك رابط الصفحة مع الربع. يتم تحديث العرض كل ٣٠ ثانية أثناء فتحه، وكذلك عند الرجوع إليه؛ زر **سجل مشترك** يجلب آخر البيانات فورًا.

## من يستطيع الاطلاع والتعديل؟

- المشاهدة متاحة لكل من يفتح رابط الصفحة، بما فيها أسماء الربع ومبالغهم وبيانات التحويل والملاحظات. هذا ليس سجلًا خاصًا خلف تسجيل دخول للمشاهدين، والرابط ليس حاجزًا أمنيًا.
- التعديل يتطلب حسابًا مسجلًا في جدول `qatta_admins`. إخفاء الأزرار مجرد واجهة؛ قاعدة البيانات تمنع تعديل الزائر والحساب غير المسؤول.
- بيانات الدخول تُدار بواسطة Supabase Auth. لا توجد كلمة مرور افتراضية أو ثابتة في الصفحة.
- عند تعديل مسؤولين في الوقت نفسه، يرفض النظام التعديل المبني على نسخة قديمة ويطلب إعادة المراجعة، بدل الكتابة فوق التعديل الأحدث.
- إضافة مسؤول آخر: أنشئ حسابه ثم نفّذ `add-admin.sql` بمعرّفه. لإلغاء الصلاحية احذف صف معرّفه من جدول `qatta_admins` في لوحة Supabase.

## النسخ الاحتياطي

اضغط **حفظ نسخة احتياطية** لتنزيل كل الدفتر بصيغة JSON. من إعدادات الاستراحة يستطيع المسؤول استيراده بعد تأكيد الاستبدال. احتفظ بالنسخ في مكان خاص؛ تتضمن الدفعات والملاحظات. النسخة التجريبية لا يمكن استيرادها إلى السجل الحقيقي.

## إذا لم يعمل الربط

- **الاتصال متعذّر:** راجع `config.js` وتأكد من تنفيذ `setup.sql` وأن مشروع Supabase متاح، ثم اضغط حالة الاتصال للمحاولة.
- **الحساب غير مسجّل كمسؤول:** نفّذ `add-admin.sql` باستخدام **User UID** الصحيح.
- **تعذّر الدخول:** راجع البريد وكلمة المرور وحالة تأكيد البريد من لوحة Supabase. تستطيع إدارة أو استعادة بيانات حساب المسؤول من مشروعك؛ الصفحة لا تحفظ نسخة من كلمة المرور.
- **لم يُحفظ التعديل:** لا تغلق النموذج؛ راجع الاتصال. إذا تغيّر السجل من جهاز آخر، أغلق النموذج وراجعه ثم أعد فتحه قبل التعديل.
- **صفحة GitHub فارغة أو 404:** تأكد من اختيار GitHub Actions مصدرًا للنشر، وأن ملفات الموقع داخل `dist`.

## تفاصيل للمطور

أموال الدفتر أعداد صحيحة بالهللات، لتجنّب أخطاء الفواصل العشرية. الدفتر صف JSONB واحد مناسب لمجموعة استراحة صغيرة، مع رقم مراجعة لتعارض التعديلات، وفحص بنية البيانات داخل PostgreSQL وعلى الواجهة. الحدود: ٢٠٠ خوي و٥٠٠ التزام في الشهر، و٦٠٠ شهر. لا يوجد تتبع أو تحليلات أو تحويل أموال تلقائي. الأسماء تُعرض كنصوص آمنة ولا تُفسّر كـ HTML.

الملفات: `dist/index.html` للصفحة، `dist/styles.css` للتصميم، `dist/app.js` للتفاعلات، `dist/config.js` للربط، `supabase/` لإعداد القاعدة. مكتبة Supabase JS مثبتة بالإصدار 2.57.4. تراخيص المكتبة والخط موجودة في `dist/assets`.

توفر الصفحة أداة WebMCP للقراءة فقط (`read_qatta_month`) عند دعم المتصفح لها؛ لا تغيّر صلاحيات المستخدم.

## حساب باسم مستخدم دون بريد شخصي

يمكن إنشاء حساب محلي مثل `hamdan` عبر Supabase Auth بالبريد الداخلي `hamdan@qatta.example` مع تأكيده يدويًا، ثم منحه الصلاحية باستخدام `add-admin.sql`. هذا عنوان داخلي لا يستقبل رسائل؛ يدخل صاحبه باسم `hamdan` وكلمة مروره. لا يمنح اسم المستخدم صلاحيات بذاته؛ يلزم وجود حسابه في `qatta_admins`. أسماء الدخول بحروف إنجليزية وأرقام وشرطة أو شرطة سفلية، بطول ٣–٣٢ حرفًا وتبدأ بحرف. إعادة تعيين كلمة مرور هذا النوع من الحسابات تتم من لوحة Supabase بواسطة مالك المشروع، وليس عبر البريد.
